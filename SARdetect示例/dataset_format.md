# 竞赛数据与预测格式

当前约定：训练标签为 `类别 x1 y1 x2 y2 x3 y3 x4 y4`；预测标签为 `类别 x1 y1 x2 y2 x3 y3 x4 y4 置信度`。类别始终在第一列，置信度仅在预测中出现且位于最后。每个目标一行，UTF-8 编码。

## 数据集目录

```text
A.dataset/contest/
├── images/                 # 原始图片，可有子目录
├── labels/                 # 对应的旋转框TXT，子目录及文件主名与图片一致
├── train.txt
├── val.txt
├── test.txt
├── manifest.json           # 文件校验与划分信息
├── taxonomy.json           # 已知层级模型的类别树，按需提供
└── class_map.json          # 外部类别到模型类别的明确对照，按需提供
```

划分文件每行是相对数据集根目录的图像路径，例如 `images/train/001.png`。没有目标的图像必须提供空标签文件，训练/验证/测试集合不重叠。

## 训练标签

```text
Car-Medium_SUV-Chevrolet_Blazer_1998 100 100 160 100 160 140 100 140
```

类别也可以是编号或普通名称：

```text
7 100 100 160 100 160 140 100 140
car 100 100 160 100 160 140 100 140
"large vehicle" 100 100 160 100 160 140 100 140
```

以上为不同类别写法的独立示例，不表示这些类别自动等价。编号当作字符串保留，例如 `007` 不会变成 `7`。名称含空格时必须使用双引号；引号是文本编码，不属于类别名。

四点坐标均为像素值，按边界顺时针或逆时针排列；不接受归一化 YOLO 水平框、交叉/退化四边形、NaN/Inf，也不在训练行末附加 difficult 或置信度。新解析器不自动猜测坐标在前的旧格式。

## 编号、名称与现役模型的关系

数据分析和检测/旋转框训练能读取编号及普通类别名。现役分类器仍绑定已有的 4/21/40 层级语义；格式支持不代表可自动识别全新类别。

若外部名称/编号对应现役类别，在数据集目录提供 `class_map.json`，键为外部类别，值为现役完整类别名称，例如：

```json
{
  "7": "Car-Medium_SUV-Chevrolet_Blazer_1998"
}
```

对照表必须真实、唯一，不能凭编号猜测。已配置映射时，分类读取使用映射后的名称，预测导出反向映射回外部编号/名称。对照表需要覆盖可能输出的类别；预测类别缺少对应项会明确报错，不会随意输出内部索引。没有官方对照表时，本项目保留现有类别名称。全新类别需另外适配分类模型及 taxonomy；仅更换文本名称不能完成模型适配。

数据集推理会自动读取该数据集的 `class_map.json`。无标签图片推理可显式指定：

```bash
python infer.py --source /path/to/images --model 1 --class-map /path/to/class_map.json
```

编号竞赛流程的 `7.infer.sh` 同样支持 `--class-map`，默认沿用配置所指数据集的对照表。

## 预测交付文件

每张输入图片对应一个 TXT，保留输入图片的相对子目录；没有预测目标也生成空 TXT。每行示例：

```text
Car-Medium_SUV-Chevrolet_Blazer_1998 100 100 160 100 160 140 100 140 0.95
```

统一测试/推理入口将文件放在本次结果的：

```text
C.results/3.infer/<实验名>/config/predictions/<模型或融合组>/<图像相对路径>.txt
```

测试结果使用 `C.results/2.test/` 对应位置。各模型/融合组分别输出，提交时选定一个输出组。`result.txt` 给出具体路径，JSON 仅作为内部诊断记录。末尾 score 保留原检测器/后处理置信度，不冒充分类概率或两者乘积。仅检测模式输出 `vehicle`，不冒充已经完成车型分类。
